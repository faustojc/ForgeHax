# ForgeHax

Minecraft utility mod for **Forge 1.12.2** (`1.12.2-14.23.5.2860`); the version comes from
`gradle.properties`. Branch `1.12.2` is the maintained 1.12.2 line. It tracks the behaviour of the
`1.20.1` branch (same module names, settings, defaults and keybind behaviour) and keeps every module
the 1.20.1 port has not re-enabled yet.

## Build

Java **8**, Gradle **4.9** wrapper, ForgeGradle **3** (`3.+`), MCP mappings `snapshot`
`20171003-1.12`. Gradle 4.9 only runs on JDK 8: point `JAVA_HOME` at a JDK 8 for every Gradle call.

```
./gradlew.bat compileJava          # fastest feedback loop
./gradlew.bat compileJava test jar # the verification bar for a change
./gradlew.bat runClient            # dev client, working directory run/
```

- `jar` is finalized by `reobfJar` and writes the `FMLCorePlugin` / `FMLCorePluginContainsFMLMod`
  manifest attributes. The jar is `build/libs/forgehax-1.12.2-<version>.jar`.
- `build` has no deploy step (there is no copy task), so it is safe, but it only adds `check` on top
  of the tasks above. Run the explicit list; CI (`scripts/cibuild`) runs `build`.
- The `forgehax.*` properties in `gradle.properties` are also runtime input: `processResources`
  tokenizes `src/main/resources/config.properties` with them, `ForgeHaxProperties` reads it, and the
  mapping loader derives the MCP archive to fetch from `forgehax.mcp.*`. Change them only together
  with the matching MCP data. If `config.properties` ships with `@...@` tokens, clean and rebuild.
- `schematica_api` is a source set of compile-time stubs for the optional Schematica mod
  (`src/schematica_api/java`); it is on the `main` compile classpath only and is not packaged.

### Dev client quirks (`build.gradle`) - do not "simplify" these away

- `extractForgeSide` plus the `runClient`/`runServer` classpath prepend: ForgeGradle 3 builds a
  1.12.2 dev jar whose `net.minecraftforge.fml.relauncher.Side` has an extra `BUKKIT` constant,
  which makes FML's `NetworkRegistry.newChannel` throw at startup. Forge's real `Side.class` from
  the universal jar goes first on the classpath. Only the Gradle run tasks get this; run configs
  generated by an IDE do not.
- `output.resourcesDir = output.classesDirs.singleFile`: FML finds `mcmod.info` next to the classes
  in a dev run.
- The `fml.coreMods.load` run property is what loads `ForgeHaxCoreMod` in dev (production uses the
  manifest attribute).

## Architecture

- `Helper` / `Globals` - static accessors for `Minecraft` (`MC`), the local player, the world, the
  mod manager, the file manager and chat printing. Almost every class extends or statically imports
  them.
- `util/mod/` - module base classes: `BaseMod`, `ToggleMod`, `CommandMod`, `HudMod`, `ServiceMod`,
  plus `Category`. `util/mod/loader/ModManager` finds modules by scanning the classpath package
  `com.matt.forgehax.mods.*` (set in `ForgeHax`) for `@RegisterMod`, and also loads plugin jars from
  `forgehax/plugins`. There is no registry: adding a module file is enough. A class without
  `@RegisterMod` is not loaded (`AutoElytra` is such a stub).
- `util/command/` - the CLI: `Command`, `CommandBuilder`, `Setting<T>`, `Options`, `CommandStub`.
  Settings are the single source of truth for module configuration. Every command and setting is
  written as JSON to `forgehax/config/settings/<name>.json` under the game directory; modules
  deserialize on load and serialize on unload. `Setting.set` does not persist by itself: the CLI
  processors and the GUI call `serialize()` after an accepted change.
- `mods/` - the modules: 100 top-level `@RegisterMod` classes, plus `services/` (always-on
  `ServiceMod`s such as `RenderEventService`, `BindEventService`, `GuiService`), `managers/`
  (shared cross-module state) and `commands/` (CLI-only commands), 125 loaded in total.
- `events/` - ForgeHax events. `RenderEventService` posts `RenderEvent` (world drawing) and
  `Render2DEvent` (HUD drawing) from Forge's `RenderWorldLastEvent` and
  `RenderGameOverlayEvent.Text`; modules listen to those, not to the raw Forge events.
- `gui/` - the `ClickGui` control centre. `gui/components/` holds the layout and state helpers
  (`ModalGeometry`, `ModuleCatalog`, `ModuleSidebar`, `GuiScrollModel`, `GuiScissor`, `GuiPalette`);
  `gui/elements/` holds the setting and keybind editors (`SettingControl`, `KeybindControl`).
- `util/draw/` and `util/tesselation/` - rendering helpers (`SurfaceHelper`, `SurfaceBuilder`,
  `RenderUtils`, `GeometryTessellator`, `font/`) on the 1.12.2 fixed-function stack:
  `GlStateManager`, `Tessellator`/`BufferBuilder`, `FontRenderer`, `ScaledResolution`.

## Bytecode injection

There is no Mixin on this branch and none may be introduced. Injection is an FML coremod:

- `asm/ForgeHaxCoreMod` is the loading plugin. `asm/ForgeHaxTransformer` registers every patch
  class from `asm/patches/` in its constructor (21 today, one `registerTransformer(...)` line each).
- A patch is a `ClassTransformer` with inner `@RegisterMethodTransformer` `MethodTransformer`s. It
  inserts a call to a static method in `asm/ForgeHaxHooks`, which posts an event class from
  `asm/events/`. Keep patches thin: module logic lives in modules.
- Names resolve at runtime through the mapping layer. `asm/TypesMc` holds vanilla classes, fields
  and methods, `asm/TypesHook` the hook methods, `asm/TypesSpecial` third-party (Schematica) targets.
  `RuntimeState` picks `ObfuscatedStateMapper` or `NonObfuscatedStateMapper`; the former builds the
  Notch/SRG/MCP tables with `MCPMappingLoader` from the MCP archive for `forgehax.mcp.*`. The first
  run downloads it (network needed) and caches it in `.cache/MCPMappingViewer` in the user's home
  directory. Dev runs load the same data.
- Private vanilla state is reached through `asm/reflection/FastReflection` (`FastReflection.Fields`).
- Prefer a Forge 1.12.2 event over a new patch when one fires at the same point.
- Adding a patch: the target and hook constants in `TypesMc`/`TypesHook`; a `HookReporter` in
  `ForgeHaxHooks` (`newHookReporter().hook(..).dependsOn(..).forgeEvent(..)`) whose hook method
  checks `reportHook()`; the patch class; its `registerTransformer` line.
- `ForgeHaxTransformer` also excludes itself from other mods' Mixin environments when one is present.
  That is compatibility only, not a Mixin dependency.

## Keybinds

- Binds are LWJGL2 `Keyboard` codes on a `CommandStub`. `Keyboard.KEY_NONE` (0) means bindable but
  unbound (`StubBuilder.bind()`); `-1` means the command takes no bind at all (`StubBuilder.nobind()`,
  and the default). They are not the same value; conflating them drops binds.
- Mouse buttons are `-100 + button` (-100 left, -99 right, -98 middle).
- Saved binds are `{"bind":N}` with no marker. A file carrying `"codes":"glfw"` was written by the
  1.20.1 build; `CommandStub` translates it once through `LegacyKeyCodes.toLwjgl2` (marked values
  0..7 are mouse button indexes) and rewrites it. Never translate an unmarked value.
- Vanilla `KeyBinding` pressed state only updates while no screen is open, so `BindEventService`
  reads the key off the input event itself: FML's `InputEvent` key/mouse events in game, and
  `GuiScreenEvent.KeyboardInputEvent`/`MouseInputEvent` while a screen is open. Input is accepted
  only with no screen, or with an idle `ClickGui` (`isCapturingInput()` is false). The key event is
  sampled in `Pre`, before the screen sees it, so the key that ends an edit or bind capture is not
  dispatched as a bind. A mouse bind that closes or replaces the screen cancels the click. Do not
  read `KeyBinding.isKeyDown()` for binds - the GUI could then never close itself.
- The GUI bind defaults to right shift (`GuiService`).

## GUI rule

Scope: the ForgeHax GUI and the files it directly needs.

- One centered, non-draggable modal (`ModalGeometry`) over a dimmed full-screen backdrop. `ClickGui`
  stays the screen type, opened by `GuiService`; `doesGuiPauseGame()` stays false. A click outside
  the modal does nothing.
- One flat module sidebar (`ModuleCatalog`): `ModManager.getMods()` minus `isHidden()`, sorted by
  name case-insensitively, with a search box over module and setting names and descriptions.
  `Category` is backend metadata; never render, group or filter by it.
- A row click selects a module; only the dedicated enabled control toggles it, via
  `enable()`/`disable()`, then persists the `enabled` setting.
- Escape, the GUI bind and the visible close control close the modal when no editor is capturing
  input.
- No animation, dragging, gradients or external GUI dependency. Colours are the `GuiPalette` tokens:
  backdrop `#080A0D`, modal `#12171D`, surface `#19212A`, divider `#2B3642`, text `#EDF1F5`, accent
  `#D9773F`.
- Layout is recalculated from the current `GuiScreen` size; clipped drawing goes through
  `GuiScissor`, which restores GL state when closed.
- Settings come from the selected module's descendant `Setting<?>` objects, sorted by name; the
  `enabled` setting appears only as the header switch. Booleans use switches, enums explicit
  choices, bounded numbers a slider plus a value field, everything else a validated text field.
- Changes go through `Setting.set`/`reset()` so callbacks and bounds stay authoritative; input that
  fails to parse is rejected, never written as `null`. The value is reread after every attempt and
  accepted changes are serialized. Binds are edited through `KeybindControl`, which wraps
  `CommandStub`.
- `Options` collections and action commands stay in the CLI; the GUI shows one passive CLI-only
  notice for them.

## Parity with 1.20.1

- For modules on both branches the user-visible surface (module names, descriptions, setting names,
  defaults and bounds, bind behaviour) stays identical.
- A behaviour fix on one branch is carried to the other when it can be expressed there. Where 1.20.1
  has a reduced behaviour forced by its API, this branch keeps the fuller 1.12.2 behaviour.

## Removed, do not resurrect

- `XrayMod`, with `BufferBuilderPatch`, the render-layer hooks and events, and the `CanRenderInLayer`
  and `RenderBlockLayer` injections.
- `TimerMod`, with its two `FastReflection` timer handles.
- Both are removed on this branch and on `1.20.1` by the owner's decision.

## Conventions

- No new dependencies. No abstraction with a single implementation.
- Read names, descriptions, settings and binds from the module APIs. Never hard-code or duplicate
  them.
- Do not refactor unrelated code. Indent with 2 spaces (`.editorconfig`).
- Unit tests cover pure logic only: GUI geometry and scrolling, bind JSON and key-code translation,
  aim/projectile/angle math, entity distance, spam tokens, fly velocity and player-name ordering.
